# Architecture Decision Records

ADRs preserve why significant architecture choices were made. They supplement—but never replace—the current-state handbook.

Use sequential files such as `0001-database-per-service.md`. Status is `Proposed`, `Accepted`, `Deprecated`, `Superseded`, or `Rejected`.

Create an ADR for service/data ownership, communication/consistency, major technology/provider choice, security/privacy strategy, compatibility, matchmaking algorithm class, deployment, or recovery policy.

When accepted, update canonical docs and implementation in the same change. When superseded, link both ADRs and retain history.

Use [`0000-template.md`](0000-template.md).
